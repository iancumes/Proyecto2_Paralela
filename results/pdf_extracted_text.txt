1. Fundamentos de DES
DES es un cifrador simétrico: la misma llave secreta permite cifrar y descifrar. Aunque el enunciado usa
“llave privada”, aquí no interviene un par de llaves pública y privada. DES transforma bloques de 64 bits y
utiliza 56 bits efectivos; los otros ocho bits de su representación se destinan a paridad. [1]
Transformación de un bloque
La permutación IP reorganiza la entrada y la divide en L_0 y R_0, de 32 bits. En cada una de las 16 rondas
se calcula L_i = R_(i-1) y R_i = L_(i-1) XOR f(R_(i-1), K_i). Después se concatena R_16 con L_16 y se
aplica IP inversa. [1]
La función f expande R de 32 a 48 bits, aplica XOR con la subllave, transforma ocho grupos de seis bits en
ocho grupos de cuatro mediante cajas S y permuta los 32 bits resultantes. PC-1 selecciona 56 bits de
llave; rotaciones de dos mitades de 28 bits y PC-2 generan las 16 subllaves de 48 bits. Para descifrar se
usan en orden inverso. [1]
Preparación del texto en esta implementación
Paso Operación que realiza el programa
1. Codificar Leer el archivo UTF-8 como bytes. Las palabras se cuentan aparte; DES trabaja con bytes.
2. Rellenar Agregar PKCS#7 hasta completar un múltiplo de 8 bytes. Se agrega relleno incluso si la longitud ya es
múltiplo de 8. [3]
3. Cifrar Aplicar DES-ECB a cada bloque completo con la misma llave. ECB no necesita vector de
inicialización. [2]
4. Guardar Escribir bytes binarios. No usar strlen para medir el criptograma.
5. Recuperar Descifrar todos los bloques, validar y retirar el relleno; buscar la frase exacta.
DES fue retirado como estándar en 2005. En este proyecto se utiliza con finalidad didáctica; ECB también expone la repetición de
bloques iguales. [2, 7]

2. Diagrama del algoritmo DES
Figura 1. Flujo de un bloque DES y generación de subllaves. Elaboración propia a partir de FIPS 46-3 [1].
Cómo leer el diagrama
La rama derecha transforma el bloque. La izquierda prepara las subllaves que utiliza cada ronda. Para el descifrado se conserva
el flujo y se invierte la secuencia de subllaves. El recuadro de f amplía la operación interna de una ronda; no representa una ronda
adicional.
Por ejemplo, invertir una ronda permite recuperar R_(i-1) = L_i y L_(i-1) = R_i XOR f(L_i, K_i). Esta identidad explica por qué la
estructura de Feistel permite recuperar los datos sin invertir individualmente las cajas S. La biblioteca ejecuta las tablas de
permutación y sustitución; nuestro programa distribuye las llaves candidatas.

4. encrypt y decrypt: funcionamiento
Las funciones reciben un índice de llave y un búfer que modifican en el mismo lugar. En el original, ambas
construyen un long k, ajustan paridad con des_setparity y llaman ecb_crypt. El parámetro DES_ENCRYPT
o DES_DECRYPT elige la dirección; el literal 16 restringe el trabajo a 16 bytes.
// Firmas reales del archivo proporcionado:
void encrypt(long key, char *ciph);
void decrypt(long key, char *ciph, int len);
// Contrato de la version corregida:
encrypt(uint64_t key, unsigned char *data, size_t len);
decrypt(uint64_t key, unsigned char *data, size_t len);
Conversión portable del índice a la llave DES
Se dividen los 56 bits del índice en ocho grupos de siete. Cada grupo ocupa los bits 7 a 1 de un byte; el bit
0 se ajusta para que el byte tenga una cantidad impar de unos. La enumeración big-endian es explícita: no
depende del tamaño de long ni del orden de bytes del procesador.
for (unsigned i = 0; i < 8; ++i)
bytes[7-i] = ((key >> (7*i)) & 0x7f) << 1;
DES_set_odd_parity(&bytes);
DES_set_key_unchecked(&bytes, &schedule);
Índice decimal Llave DES de 8 bytes, con paridad
8,192 0101010101018001
135,168 0101010101104001
249,856 01010101011f4001
DES_set_key_unchecked prepara el calendario de subllaves y permite enumerar también llaves débiles.
DES_ecb_encrypt procesa un bloque de ocho bytes en la dirección indicada. Estas funciones están
obsoletas desde OpenSSL 3.0; se eligieron para adaptar el ejercicio y mantener visible el costo por
candidato. [2]
La conversión nueva es una definición explícita del índice; no pretende reproducir la conversión defectuosa del original. Para
comparar resultados entre equipos debe conservarse esta misma convención.

5. tryKey: comprobar un candidato
Figura 3. Comparación del flujo original y el flujo corregido de tryKey.
En el original, temp[len+1] es un arreglo local de longitud variable. memcpy copia el criptograma;
temp[len]=0 reserva un final de cadena; decrypt modifica la copia y strstr determina si aparece search. El
retorno es booleano: 1 cuando el puntero obtenido es distinto de NULL y 0 en otro caso.
En la corrección, scratch se reserva una vez por proceso, evitando crear un arreglo grande en la pila para
cada llave. Cada intento descifra el mensaje completo. Después se valida el relleno, se fija
scratch[plain_len]=0 y se ejecuta strstr. Un relleno inválido descarta el candidato; la frase sigue siendo
necesaria para aceptarlo.
La función nunca modifica cipher. Por eso todos los intentos parten de los mismos bytes. Si se descifrara
repetidamente el mismo búfer sin restaurarlo, el segundo intento recibiría el resultado del primero y la
búsqueda dejaría de ser correcta.
La frase reduce falsos positivos, pero su presencia no constituye una prueba matemática de unicidad. En los experimentos,
además se comprobó fuera del tiempo medido que la llave hallada fue la utilizada y que el archivo recuperado coincidió byte por
byte con el original.

6. memcpy: conservar el criptograma
void *memcpy(void *destino, const void *origen, size_t n);
memcpy copia n bytes del origen al destino y devuelve el destino. No agrega un terminador ni se detiene
ante un byte cero; las regiones no deben superponerse. [4, §7.24.2.1]
Figura 4. Copia de bytes binarios y terminador agregado por el programa.
Dentro de este programa
La copia inicial permite cifrar un búfer sin perder el texto de referencia. En tryKey se copian exactamente
len bytes de cipher a scratch. Cada proceso tiene su propio scratch; MPI no comparte ese puntero entre
procesos. El ejemplo de la figura copia el byte 00 de la segunda posición, igual que cualquier otro byte.
El espacio adicional permite escribir el terminador. Ese byte lo escribe el programa, no memcpy. Colocarlo al final evita leer fuera
del búfer, pero no elimina posibles ceros internos de un descifrado incorrecto. Por esta razón la longitud del criptograma proviene
del archivo, y no de strlen(cipher).
El costo de la copia es lineal en len. En nuestras mediciones se incluye en cada intento, junto con la preparación de subllaves y el
descifrado completo; todas las configuraciones ejecutan el mismo trabajo por candidato.

La frase ciencia con paciencia aparece en el segundo párrafo, comienza en el desplazamiento de byte

8. Coordinación de los procesos MPI
Figura 6. Flujo colectivo de la búsqueda paralela.
MPI_Bcast distribuye el criptograma desde rank 0. Cada proceso conserva una copia y prueba sus candidatos. Cada lote termina
con MPI_Allreduce(MPI_MIN): el valor UINT64_MAX representa “sin hallazgo” y cualquier índice válido lo reemplaza. El colectivo
entrega el mismo resultado a todos. [5]
Todos ejecutan la misma secuencia de colectivos, incluso los ranks cuyo rango ya se agotó. El modo early termina al detectar una
coincidencia global; full continúa hasta cubrir el espacio completo. De esa forma también se resuelve el caso sin coincidencia sin
esperar mensajes inexistentes.
El lote de 128 amortiza la coordinación a cambio de trabajo adicional antes de detenerse. En la ronda ganadora, cada rank
distinto del ganador puede completar hasta 128 intentos. La memoria total crece con P, mientras que el mensaje de reducción
contiene solo un índice de llave.

8.1 Distribución del espacio de llaves
El intervalo se define como [L, U), con W=U-L. Para P procesos: q=floor(W/P) y r=W mod P. El rank i
recibe c_i=q+1 si i<r y q en otro caso. En la estrategia contigua su inicio es a_i=L+i*q+min(i,r). Cada rank
prueba [a_i, a_i+c_i), sin huecos ni duplicación.
En la estrategia cíclica, rank i prueba L+i, L+i+P, L+i+2P, mientras la llave sea menor que U. Su cantidad
es cero si i≥W y, en otro caso, 1+floor((W-1-i)/P). La diferencia entre cantidades asignadas no excede una
llave.
Figura 7. Ubicación de las tres llaves frente a particiones contiguas de 2 y 4 procesos.
Orden de búsqueda y tiempo hasta el hallazgo
Si W es divisible entre P y la llave es K, en intervalos el ganador realiza d=(K-L) mod (W/P)+1 intentos. En
cíclica realiza d=floor((K-L)/P)+1. Otros ranks pueden completar el lote de la ronda ganadora. Estas
expresiones describen posiciones, no una reducción del costo criptográfico por llave.
Para la llave original K=2^54 y el espacio completo W=2^56, P=4 coloca K exactamente al inicio del rango de rank 1; P=8 la
coloca al inicio de rank 2. Una búsqueda secuencial desde cero requeriría K+1 intentos. Este caso muestra por qué una llave
elegida favorablemente puede distorsionar el speedup.

9. Texto elegido y cifrado completo
350 palabras, contadas por separación en espacios en blanco; 2 557 bytes UTF-8, incluidos saltos de
línea. Frase exacta: ciencia con paciencia. El texto se redactó para este ejercicio.
La computación paralela permite resolver problemas mediante la cooperación de varios procesos que trabajan sobre una misma
meta. Cada proceso recibe una parte del trabajo y utiliza sus propios recursos para avanzar. Cuando el problema puede dividirse
con claridad, esta organización reduce el tiempo necesario para obtener resultados y facilita experimentar con soluciones que
serían demasiado lentas en una ejecución secuencial.
En este proyecto estudiamos una búsqueda exhaustiva de llaves para comprender tanto sus posibilidades como sus limitaciones.
El mensaje que protegemos describe una experiencia universitaria: un equipo prepara datos, escribe programas, revisa errores y
comparte conclusiones sustentadas en evidencia. Nuestra frase de verificación es ciencia con paciencia, porque encontrar una
respuesta correcta exige procedimientos cuidadosos y observaciones que puedan repetirse.
El cifrado transforma los bytes del mensaje en bloques que parecen carecer de sentido. Para recuperar el contenido original se
necesita aplicar el procedimiento inverso con la llave adecuada. Si esa llave se desconoce, podemos enumerar candidatos,
descifrar una copia del mensaje y buscar una frase suficientemente específica. Esta estrategia ilustra por qué el tamaño del
espacio de llaves influye directamente en el esfuerzo requerido.
La distribución del trabajo también cambia la interpretación de los tiempos. Una llave cercana al inicio del recorrido puede
aparecer pronto, aunque existan muchas combinaciones pendientes. Otra situada al final obliga a realizar más intentos. Además,
cuando repartimos intervalos entre procesos, una llave grande puede quedar al comienzo de un intervalo y producir una
aceleración aparente especialmente alta. Por eso debemos contar intentos y comparar varias posiciones.
Una evaluación responsable conserva el mismo mensaje, documenta el equipo utilizado y repite cada medición. También
distingue el tiempo dedicado al cálculo del empleado en coordinar procesos. Los promedios ayudan a resumir resultados, pero la
dispersión revela variaciones que una sola ejecución ocultaría. Finalmente, compartir el código, los comandos y los datos permite
que otras personas revisen nuestras decisiones. Así, el aprendizaje combina fundamentos de criptografía, programación
distribuida y análisis experimental para explicar resultados con honestidad y precisión. La meta consiste en entender el
comportamiento y reconocer qué conclusiones necesitan pruebas antes de generalizarse a distintas redes.

Definición exacta del tiempo
Cada corrida inicia con MPI_Barrier. Cada rank mide una duración local con MPI_Wtime y se toma el
máximo mediante MPI_Reduce(MPI_MAX). Así no se comparan marcas absolutas de relojes distintos. El
intervalo incluye tryKey y los Allreduce; excluye arranque de mpirun, lectura, cifrado, escritura y
recolección posterior de estadísticas. [6]
media = sum(T_j) / 5
sd = sqrt(sum((T_j - media)^2) / 4)
S_P = media(T_1) / media(T_P)
E_P = 100 * S_P / P
R_P = media(intentos totales) / media(T_P)
T_1 es el mismo programa corregido con un proceso, para la misma llave, modo y estrategia. sd es la desviación estándar
muestral; las barras de error muestran ±sd. En early, S_P se llama aparente porque puede cambiar el trabajo total. En full, se
prueban exactamente 262144 candidatos por corrida y se mide escalamiento con trabajo constante.
No se descartaron valores atípicos de las cinco repeticiones. Las aplicaciones del equipo y el planificador pueden introducir
variación; no se afirma aislamiento térmico ni afinidad a un tipo concreto de núcleo.

13. Por qué unas llaves aparecen antes
La magnitud numérica de una llave no hace más costoso descifrar un bloque DES. El costo cambia
principalmente por cuántos candidatos se prueban antes de llegar a ella, por el reparto y por el tiempo
hasta comunicar el hallazgo. Con longitud y algoritmo fijos, el trabajo de una prueba sigue siendo
esencialmente el mismo.

Interpretación del speedup aparente
En intervalos, K=135168 está 4096 posiciones después del inicio 131072 para P=2, 4 y 8. Todos esos
casos tienen la misma profundidad local de 4097 candidatos. El tiempo no se divide nuevamente entre dos
al duplicar P; incluso puede aumentar por espera. Una eficiencia aparente superior al 100% refleja una
búsqueda diferente, no capacidad de cómputo creada por MPI.
En cambio, K=249856 conserva un recorrido largo dentro de su rango y muestra aceleraciones más
moderadas. K=8192 es un caso desfavorable para intervalos porque no se reparte el prefijo que debe
recorrer rank 0. Seleccionar únicamente la llave central daría una conclusión sesgada.
Si la llave fuera uniforme en todo el rango
Sin considerar lotes y suponiendo tasas iguales, la profundidad esperada del ganador es aproximadamente W/(2P) tanto con
intervalos como con cíclica. Sin embargo, para una misma llave individual, los intervalos pueden presentar saltos bruscos al
cambiar P. Tres llaves ilustran este mecanismo; no estiman por sí solas el rendimiento promedio de todas las llaves posibles.
El modo full mantiene el trabajo total y responde a otra pregunta: cuánto acelera MPI una carga fija. Ambos experimentos son
útiles, siempre que se informe qué se está comparando.

14. Alcance y conclusiones
Lo demostrado con las mediciones
La implementación cifra todo el mensaje y recupera sus bytes originales mediante búsqueda de
candidatos. Los rangos tienen cobertura completa, las dos distribuciones terminan colectivamente y el
caso sin coincidencia está probado. La búsqueda acepta cualquier índice DES válido y límites hasta 2^56.
La distribución por intervalos produce resultados muy sensibles a la ubicación de K. La cíclica reduce esa
sensibilidad en búsquedas desde un límite conocido. El experimento de trabajo fijo permite evaluar el
escalamiento sin atribuir a MPI el beneficio de una llave favorable.
Demostración adicional en el espacio de 56 bits
También se cifró el mensaje con la llave del archivo base, K=18014398509481984=2^54, y se buscó con
P=4 sobre [0,2^56). En cinco corridas, rank 1 encontró esa llave con media 0.003005 ± 0.000070 s y 385
intentos totales por corrida. El resultado es posible porque la llave ocupa la primera posición de su rango;
no representa explorar todo DES.
Límites de lo que se puede concluir
Las 180 mediciones principales utilizan 2^18 candidatos. No se recorrieron exhaustivamente las 2^56
llaves. Los ensayos de llaves grandes prueban direccionamiento y parada temprana en posiciones
conocidas; no demuestran un tiempo práctico para romper una llave arbitraria de 56 bits.
La tasa secuencial media en full fue aproximadamente 45,339 candidatos/s. Mantenerla sobre 2^56 candidatos daría unos 50,362
años para el peor caso y la mitad en promedio bajo una llave uniforme. Es una extrapolación lineal orientativa del programa, no un
resultado medido ni una estimación de hardware especializado.
Los procesos se ejecutaron en una sola máquina. Para generalizar a memoria distribuida entre máquinas faltaría repetir la matriz
con una red real, documentar latencias, arquitectura de cada nodo y política de afinidad, y ampliar el muestreo de llaves. El
código emplea tipos MPI de ancho explícito y envía bytes del criptograma para favorecer portabilidad.
